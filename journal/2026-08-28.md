# 2026-08-28

## Project bootstrap

Created `temprun` as a hands-on Temporal learning lab for distributed-systems and agent-runtime interview preparation.

The first toy problem is a durable research workflow that will:

- accept a research request;
- fan out to three fake agent Activities in parallel;
- collect their results;
- synthesize them;
- later wait for human approval via Signal;
- survive retries and worker restarts without losing logical workflow progress.

The immediate goal is not sophisticated agent behavior. Fake Activities are preferred so the learning surface stays focused on Temporal execution semantics.

## Temporal concepts to learn through the project

- Workflow vs Activity
- deterministic replay and event history
- Activity retries and timeouts
- at-least-once Activity execution and idempotency
- parallel fan-out/fan-in
- Signals and durable waiting
- Queries
- Child Workflows
- cancellation and heartbeats
- task queues and worker concurrency
- worker crash/restart behavior
- Continue-As-New and long histories
- deployment/versioning of long-running Workflows

## Planned failure experiments

1. Fail one Activity and observe Temporal retry behavior.
2. Kill a worker while an Activity is running, restart it, and inspect recovery.
3. After Signals are added, kill the worker while the Workflow waits for approval and verify that logical waiting survives.
4. Simulate an external side effect followed by Activity failure to understand why Activities need idempotency.

## Memory correction

The first attempt at project memory incorrectly modeled `CONTEXT.md`, `DECISIONS.md`, `LEARNINGS.md`, etc. as separate source primitives inside `.memory/`.

Chronelle's current model is simpler: source memory is Claim and Commitment; `MEMORY.md` is the current-status projection; `journal/` is the dated paper trail; compact `.chron` records are stored beneath `.memory/records/YYYY/MM/DD/`.

## First workflow increment

Implemented the first Temporal learning slice:

- `ResearchWorkflow` coordinates the durable workflow.
- `plan_research` is the initial planning Activity.
- `run_fake_agent` runs three fake agents in parallel: `web`, `systems`, and `critic`.
- `synthesize_research` combines agent results into a `ResearchBrief`.
- `ResearchRequest.fail_agent_once` injects one controlled Activity failure.
- `RetryPolicy` is configured on fake agent Activities, so retry behavior is Temporal-managed rather than a manual Workflow loop.

Added Temporal integration tests using `WorkflowEnvironment` and `Worker`.

Observed behavior:

- Happy path returns a synthesized brief with all three agent findings.
- When `fail_agent_once="systems"`, the systems Activity fails on attempt 1 and succeeds on attempt 2.
- The Workflow code remains deterministic and only coordinates Activity execution.

Verification:


The first run required network access so the Temporal SDK could download its local test server binary.
